SWAW Kit is a portable development and project-control Entry bound to a project directory.

The command directory is the command address. Every runnable command directory contains exactly one supported run.* entry, and Proj Core derives the Catalog from the real directory tree.

Commands declare required Provider contracts and provided Export contracts in swawkit.module.json. Inspect execution readiness with the read-only command:
  {{COMMAND}} .check <command-address> [--json]

`.check` reports whether the command entry and its declared inbound dependencies are ready. Normal execution repeats the same read-only dependency assertion before the Journal and target process. Checks never install, build, repair, or execute domain code; each run.* owns its dynamic domain validation.

The thin EXE Launcher owns Entry addressing, Host/CLI routing, and the native argv boundary. `<entry>.exe` maps uniquely to canonical `data/proj.<entry>`, whose Runtime selector is `runtime/current`. Normal execution reads no second identity file. Only the manager `swawkit.exe` may cold Bootstrap a missing Runtime; ordinary Entries fail closed and must be created or repaired through the manager.

_lib\proj\build.ps1 writes only App and Launcher candidates below data/proj_cache/bootstrap/build. project/proj/build/launcher likewise publishes only its command-local export/swawkit.exe. Neither replaces the root Launcher, and there is no publish/launcher, Launcher-template, or Favorites publication path.

System commands begin with one dot and use slash-separated paths, for example {{COMMAND}} .entry/language or {{COMMAND}} .context. Module commands begin with an explicit namespace, for example {{COMMAND}} project/build. The CLI does not accept system/, module/, or legacy dot-separated forms. `.entry` and `.runtime` manage the Entry lifecycle. Launch {{COMMAND}} without arguments to start or activate the local Web console.
