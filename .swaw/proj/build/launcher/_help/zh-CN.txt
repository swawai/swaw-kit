使用已发布并完整复验的 Bootstrap builder 环境构建 Proj 原生 Launcher。

用法:
  {{INVOCATION}}

没有可用 Entry 时，也可以从源码树直接运行：
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File _lib\proj\build.ps1

构建中间文件和最近一次成功结果保存在当前命令专有数据根：
  work/launcher/
  export/swawkit.exe
  export/manifest.json
  _state.json

日常 Module 命令直接读取 `data/proj_cache/bootstrap/environment.json`，并核对
`bootstrap.json`、编译器与链接器的路径、长度和摘要；它不消费 Entry Config 或
`.dev/setup`，也不依赖系统 PATH 中碰巧存在的编译器。没有可用 Core 时，源码树入口
`_lib/proj/build.ps1` 仍使用同一 Bootstrap 固定工具链恢复构建；两条路径共用同一份
`_lib/proj/_launcher/build.json` 编译契约，但 Module 的 work/export 不写入共享缓存。
它只发布模块自己的 `export/swawkit.exe`，绝不修改根目录下正在使用的 swawkit.exe。
不存在 `project/proj/publish/launcher`，也不会向 Favorites 发布 Launcher 模板。根 Launcher
与改名后的 Entry 副本由源码包或显式部署提供；未来若需要在线替换，应由独立 updater
协议负责。

Launcher 复制并改名后的 Entry 必须直接放在 SWAWKIT_HOME 根目录。无参数启动 Host、
托盘和本地 Web 控制台；带参数时同步执行 Rust CLI，保留原生参数边界并返回真实退出码。
放入子目录后会拒绝启动。

该 Module 命令不接受动态参数。Launcher 编译和候选原子落盘只有这一条组件主路径。
